## 背景：3cm 偏差是怎么来的

动态测量（94cm 路径，23 趟）读到 **97.12 ± 0.62 cm**，高出真值 **+3.32%**。
它**不是一个误差，是两个方向相反的效应抵消后的净值**：

| 效应 | 大小 | 来源 |
|---|---|---|
| 视差放大 | **+8.15%** | 车标高出桌面 11cm，单应矩阵按桌面标定 → H/(H−h) = 146/135 |
| 刻度偏差 | **−5.11%** | 点击桌面上同样两点读 89.2cm（真值 94），成因未确定 |
| **净值** | **+3.32%** | ≈ +3cm |

### ⚠️ 最关键的一点

**只修视差，误差会从 +3.1cm 变成 −4.8cm（绝对值更大）。**
所以"消除 3cm"必须**两项都解决**。这点下次要和 Kevin 说明。

### 视差的几何（Kevin 说的"画面中心定为 (0,0)"）

相机在正上方，系统把看到的一切**当作贴在桌面上**。车标高出 11cm，于是它被"推"向外侧：

```
        📷
        │╲
        │ ╲          ← 视线
   ─────┼──🚗────    ← 真实位置（高 11cm）
        │   ╲
   ═════╧════✗══     ← 系统认为的位置（偏外）
     正下方(0,0)
```

- 车在**相机正下方** → 视线垂直 → **零误差**
- 越往外 → 视线越斜 → **偏得越多**
- 数学上：以正下方点为中心，**所有坐标向外放大 H/(H−h) 倍**

**修正**：坐标以正下方点为原点，乘 **(H−h)/H = 135/146 = 0.9247**。

### 刻度偏差的猜想（待验证）

GoPro 在 webcam 模式下**自己会做镜头矫正**。若它矫正过头（枕形畸变），画面边缘被拉伸 → 位于边缘的角标显得更大 → 算出的比例尺偏小 → 所有距离读短。

这与"自己再开畸变矫正会过矫正"的现象一致（画面已被矫正过一次）。

## 阶段一：消除 3cm 偏差

### 步骤 1.1　工具准备〔Claude 做〕

新增一个按键，把**当前所有检测到的标记**记录到 CSV：
- 标记 ID
- 在俯视图中的位置（cm，相对相机正下方点）
- **表观尺寸**（cm，用当前比例尺换算）
- 离正下方点的半径

有了它，做实验就只需"摆好位置 → 按一下键"。

### 步骤 1.2　确定相机正下方点〔Claude 做〕

把原始画面的中心（≈主点，标定显示偏差仅 0.4%）通过单应矩阵 M 投影到俯视图，得到 **(0,0)**。
在画面上画一个十字标出这一点，方便实验时对齐。

### 步骤 1.3　实验 A：平放的码 → 测畸变〔你做，约 20 分钟〕

**目的**：验证"边缘的码是否显得更大"（即刻度偏差的成因）。

**准备**：一个**平放**的 ArUco 码（备用 ID，不要用角标 0–3），用尺量出**黑色方块的真实边长**并记下。

**做法**：把码平放在桌面上，依次放到这些位置，**每个位置按一下记录键**：

| # | 位置 |
|---|---|
| 1 | 正下方点（十字处） |
| 2–3 | 沿 **x 轴**（水平）向左、向右各约 30cm |
| 4–5 | 沿 **x 轴**向左、向右各约 60cm（或到边缘） |
| 6–7 | 沿 **y 轴**（垂直）向上、向下各约 30cm |
| 8–9 | 沿 **y 轴**向上、向下各到边缘 |

> 每个位置确认 `Detect:` 是绿色再按键。

**预期**：
- 若表观尺寸**随半径增大** → 枕形畸变确认，刻度偏差找到成因 ✅
- 若各处尺寸**一致** → 畸变不是原因，另找（我会接着查）

### 步骤 1.4　实验 B：抬高的码 → 测视差〔你做，约 20 分钟〕

**目的**：验证视差模型（误差在中心为零、随半径线性增长）。

**准备**：把车（或把码垫高到 11cm 的任何物体）放在桌上，**量准码面离桌面的高度 h**。

**做法**：和实验 A **相同的 9 个位置**，每个位置：
1. 在桌面上**标出车的真实位置**（比如在车底中心贴个点）
2. 按记录键
3. 记下真实位置的坐标（用卷尺量到十字的距离）

**预期**：
- 中心处误差 ≈ 0
- 误差随半径**线性增长**，方向朝外
- 斜率 ≈ 8.15%

### 步骤 1.5　实现修正〔Claude 做〕

根据实验结果实现：
1. **视差修正**：坐标以 (0,0) 为原点乘 (H−h)/H
2. **h 的自动推算**（可选）：由码的表观尺寸反推
   `h = H × (1 − S真实 / S表观)`
   ——这就是 Kevin 说的"车标打印维度设置为多少"的用处：知道 S 才能反推 h
3. **畸变/刻度修正**：视实验 A 结果而定

### 步骤 1.6　验证〔你做，约 20 分钟〕

按之前的停车端点协议，重跑 **5 趟** 94cm 路径：
```bash
python evaluation/trajectory_eval.py evaluation/traj_XXXX.csv --truth 94 --gates
```
**目标：均值落在 94 ± 0.6cm 内**，即偏差 ≈ 0。

## 阶段二：多车 + 标志合规判断

> 目标：识别多辆车和多个标志的坐标，判断每辆车**是否遵守标志**
> （遇 STOP 有没有停？遇限速有没有减速？还是直接冲过去？）

### 现状（已查代码）

| 部分 | 状态 |
|---|---|
| 标志检测（YOLO） | ✅ 已能给出位置 + 类型 |
| 车辆追踪 | ⚠️ `CAR_ID = 4` **写死单车**，6 处引用 |
| 速度计算 | ⚠️ 无持久化的每车速度 |
| 合规判断 | ❌ `STOP_SPEED_THRESHOLD`/`_stop_event` 只有定义和显示，**判断逻辑未实现** |

### 步骤 2.1　多车追踪

- `CAR_ID = 4` → `CAR_IDS = {4, 5, 6, ...}`
- 每辆车维护自己的状态：位置历史、速度、当前所属标志区
- 车辆消失/重现的处理

### 步骤 2.2　车–标志关联

- 每个标志定义一个**影响区**（进入该区即"正在通过此标志"）
- 每帧判断：每辆车在哪个标志的影响区内

### 步骤 2.3　合规判断

| 标志 | 判据 |
|---|---|
| STOP | 在影响区内**是否出现过速度 < 阈值**（真正停住） |
| 限速 55 | 通过区内的**速度是否下降**（对比进入前） |
| 红灯 | 是否停住 |
| 绿灯 | 可通行 |

进入/离开影响区时触发判定，记录事件（车 ID、标志、合规与否、时间）。

### 步骤 2.4　验证

单车逐个标志测 → 多车同时测 → 记录事件日志核对。
